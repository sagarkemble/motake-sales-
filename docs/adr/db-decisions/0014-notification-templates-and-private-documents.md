# Messages go through hand-entered templates; Documents are private PDFs sent by WhatsApp media id

WhatsApp refuses free text to a Customer who has not messaged in the last 24 hours, which is almost every business message. So every message now goes through a `notification_templates` row and no free text is ever sent. Developers insert template rows by hand in the database; the app has no write path for them. A row is never edited except to flip `verified`; a change is a new `version`. Rows are unique on (`provider`, `template_id`, `language`, `version`), where `template_id` is the provider's own template name. `template_variables` is the ordered JSON list of blank names, and `document_type` (`none`, `image`, `pdf`) says whether the template carries a document. `provider` is `whatsapp` or `sms`; SMS has no sender yet.

A caller names a template by provider + `template_id` and passes values by name. The notification service picks the highest version in the Customer's `preferred_language` (`mr` default, `hi`, `en`, on `customers`; set only when the Customer is added and never changed afterwards). If that version is not `verified`, or none exists in that language, the message is refused; there is no fallback to an older verified version, so a new version is inserted only after the provider approves it. Values must match `template_variables` exactly (no missing, no extra, no empty) and are sent in list order. The attachment must match `document_type`; an SMS template with a document is refused. A resend is refused once a newer version of its template exists, because the provider knows only the template name and language, not our version.

`notifications` gains `notification_template_id` (FK, restrict: the exact version used), `template_values` jsonb, `attachment_type` (`image`, `pdf`) and `attachment_filename`. `attachment_url` becomes `attachment_key`. `body_text` stays but is nullable and unused for now.

Documents (Bill, Note and Payment receipt PDFs) are drawn by an in-app PDF module from layouts kept in code (no layout table), always in English, and stored in a separate private R2 bucket. `bill_versions.pdf_url` and `notes.pdf_url` become `pdf_key`: the R2 object key, set once. The single exception is Correct IRN, which draws a new PDF and replaces the key on the latest version; the old object stays. A Payment receipt has no column of its own; its key lives only on the message, and it prints the seller from current Settings because Payments keep no seller snapshot. The uploaded IRN signed QR image is private too: `bills.signed_qr_image_url` becomes `signed_qr_image_key`. Nothing is reachable by a public link: browsers get a 5-minute signed link, and the notification service reads the object directly, uploads it to WhatsApp, and sends by media id. `notification_media` caches that id per (`provider`, `object_key`) and it is reused until a day before WhatsApp's 30-day expiry, then uploaded again.

**Considered:** free text inside the 24-hour window (almost never open for Bills); falling back to the latest verified version (silently sends an older wording); public R2 links like product images (anyone holding the link reads the shop's Bill); a `bills` cancelled column (not needed: the Cancel flow already marks a cancelled Bill).
